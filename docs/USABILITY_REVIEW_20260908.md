# HabHub usability and production polish

Base: `b4a19cf`, branch `codex/usability-polish-20260908`.

## Findings and implementation plan

1. **First value takes too long.** Guided setup still traverses five configuration pages and a generic choice adds eleven trackers. Move guided setup into the real Today page after name and interest cards, keep detailed/classic setup available, and start with a small goal-relevant dashboard. Keep advanced controls discoverable after setup.
2. **Tutorials compete with the task.** The library promotes the 98-step course too strongly; first-visit lessons can repeat learned content and overlap typing. Prioritize a short first guide, organize the library, preserve the full Watch/Practice course, suppress repeat prompts, and make reading time independent of animation preferences.
3. **Visual hierarchy and accessibility need consistency.** Small help text, heavy labels, tiny selected-state controls, and a featureless settings drawer make the app harder to scan. Improve shared typography, touch targets, light/dark contrast, keyboard focus, bounded sheets, and Today readability. Add a compact route directory so secondary pages are available without crowding the tab bar.
4. **Popular social threads can show wrong totals.** A shared 1,000-row response limit silently undercounts reactions/comments and may omit the viewer's reaction. Return authorized aggregate counts, fetch comments with bounded cursor pagination, and fence stale refresh/mutation results by account/group/target.
5. **Creative does not consistently show the benefit.** Some titles are clipped or covered, some captures show empty periods, and enlarged captures look soft. Refresh authentic demo captures, show meaningful histories, use measured benefit-led layouts, and inspect the resulting images and videos.
6. **Small body changes disappear into sprite thresholds.** Replace the runtime atlas selection with a continuous vector contour driven by separate weight, fat and lean-mass signals. Preserve silhouette/shaded appearances, reconcile impossible composition inputs only for rendering, and test sensitivity and extreme limb clearance. This is an illustrative estimate, not a body scan or individually validated prediction.
7. **The group schedule does not match the personal calendar.** Replace its list-only layout with familiar week/time-grid and expandable month navigation, limited to shared group items. Add opt-in timed event reminders with bounded due processing and per-group notification preferences; preserve member/creator/admin access rules and revision conflict handling.
8. **Small interaction inconsistencies hide useful actions.** Restore readable, theme-contrasting Done labels in both workout edit modes, separate the member-profile safety card from the badge showcase, and make challenge participant names/avatars open their member profiles outside edit mode.
9. **Multiple memberships need independent publication.** Personal logs must reach every eligible joined group without switching pages. Scope relational identities by destination, keep notification preferences and aliases independent, preserve group-specific configuration, and make privacy withdrawal account-wide with bounded repair/retry work.
10. **Attachment references need server ownership checks.** A group-visible row must not itself authorize somebody else's private media. Enforce ownership at the database boundary, preserve legitimate sharing and existing discussions, and reserve ambiguous photo-social identities fail-closed.

## Implemented and verified

A four-part inline coach lets users choose visible trackers, toggle trackers/to-dos, try an actual log and explore; it preserves existing history and never manufactures personal entries. Progress resumes after reload. Classic retains its five configuration pages. A global Skip all tutorials control suppresses automatic tips on every page while manual guides remain available in Quick Guide.
- Real-browser onboarding checks passed all 12 scenarios at 320, 390 and 1440 CSS pixels: distinct Guided/Classic flows, persisted global suppression, reload/resume, real logging, preservation of existing entries, manually opened guides and first-setup navigation from Quick Guide. Testing caught a route-stack remount racing the final onboarding save; completion now waits for persistence before its screen owns the navigation. Evidence: `store/exports/onboarding-web/report.json`.
- Quick Guide emphasizes live personalization and basics, with optional focused, advanced and complete courses. Watch pacing respects reading time; native screen readers start paused, while web no longer mistakes React Native Web's always-true screen-reader stub for detection.
- Added a searchable menu directory, readable shared controls, visible keyboard focus, bounded help/selection sheets, single-tap Today editing, and centered desktop content. Narrow Today rows reserve more room for text. Help buttons have explicit 44-pixel targets.
- Fixed monthly/yearly tracker chart axes using a different date series from the plotted values. Today, tracker-detail and Progress numeric formatting now follows the chosen language. The localization scanner also checks explicit translation calls and onboarding mode descriptions.
- Added demo sleep history and a richer Progress selection. Food history now has three plausible meals per day with coherent calories/nutrients and nonduplicating sidecars; the current demo remains 1,720 kcal, with a 520-kcal breakfast. Progress-photo timeline/history uses uncropped previews; collage crop controls are unchanged.
- Group Schedule now offers Day/Week/Month views, slot drilldowns, date/time pickers, shared events, group tasks and reminders. Calendar reads use bounded 250-row cursor pages and include old overlapping events. Tests cover 761 rows, custom week boundaries, 23/25-hour DST days, invalid skipped times and privacy isolation. Shared timed reminders are opt-in, idempotent and revalidated after edits/deletes; idle cron passes do no HTTP work and reminder bookkeeping causes no workspace refresh.
- Both workout edit exits now explicitly preserve a contrasting Done label instead of allowing the theme mapper to recolor it to the button background. The safety card has standard 12-pixel separation; challenge member identities link to profiles without interfering with editing.
- A real-browser baseline traversed all 98 tutorial steps, but the final action audit found that traversal alone did not prove demonstrations ran. Watch now uses explicit, sandbox-only handlers and cannot fabricate observed-action completion; Practice still uses actual taps and drags. PostgreSQL tests cover 1,500 reactions, 1,203 comments, tied timestamps, blocked authors, outsiders, anonymous callers and privacy fences. Migration `202609080005` was applied; a subsequent dry run reported the remote database up to date.

Real long-press enters workout editing; its Done button measures 44 pixels high with 4.93:1 contrast. Challenge participant navigation, exactly 12-pixel badge/safety separation and 44-by-44 help targets were verified. Final rerun evidence is in `store/exports/usability-web/report.json`.
- The final group-calendar browser suite passed all nine scenarios at those same widths, including view navigation, timed event creation with a 15-minute reminder, conversion to all-day with reminder clearing, opt-in toggles, and empty-slot long-press creation. - The matching group reminder workers and migration `202609080006` are deployed. Remote schema parity, the minute cron, enabled dispatch, canonical Vault worker URL, and configured secret were checked without exposing secret values. An authenticated empty-work request returned HTTP 200 with zero staged, dispatched, or failed reminders. This establishes worker authentication/configuration, not physical-device delivery.
- Final scale review found another silent 1,000-row limit in push audience/device discovery. The worker now keyset-pages memberships, registrations and retry checkpoints, uses bounded 100-recipient query chunks, and checks both block directions within those chunks. Regression fixtures cover 1,205 members, 2,305 registrations per provider, 2,306 owner-bound checkpoints, late opt-outs/blocks/departures and later-page failures. The 100,000-row worker safety fence fails retryably before acceptance instead of silently dropping recipients; this is a bounded worker, not evidence of unlimited fan-out.
- Multi-group review caught account-wide updates using the open group's preferences and private nicknames. Events now resolve their own group settings and actor aliases; personal-setup navigation no longer hides updates from joined cloud groups. Tests confirm a muted Group A cannot suppress Group B's five event categories, changing the open group leaves the account event list unchanged, and each group's reminder opt-in remains independent.
- Personal activity publication now drains all eligible destinations in bounded foreground batches; native background publication rotates through at most eight destinations per pass. Each group has its own projection identity, configuration guard and acknowledgement. Explicit deletions withdraw the owner's source everywhere; inferred destination cleanup does not erase another group's copy. Tracker restrictions atomically withdraw historical detail across joined groups, followed by one committed-revision repair for permitted entries, photos and summaries. Tests cover stale acknowledgements, retries, membership changes and concurrent repair generations.
- The actual publication digest was exercised with 23 groups and 50,000 owned entries. Cold queue calculation was about 90–125 ms locally; 100 repeated scans stayed below 1 ms with zero repeated history reads. Immutable history/configuration/privacy changes invalidate the appropriate cache. These measurements are local fixtures, not production load certification.
- The photo ownership migration preserves media files while quarantining invalid cross-owner references. Restricted photo-social bindings prevent ambiguous or reused source IDs from exposing another owner's discussion; legitimate legacy comments, reactions, multiple-group sharing and same-owner restoration remain supported. The bindings are restricted pseudonymous security metadata, not anonymous data. PostgreSQL regression tests pass in the standard group-history gate.
- Attachment namespace ownership also covers entries, chat, avatars, media assets and challenge artwork. Server-bound challenge uploaders support legitimate administrator uploads; deleting or resetting an uploader removes their image reference from surviving challenges without deleting another creator's challenge or artwork. The actual patched account-reset RPC and auth-user deletion cascade pass PostgreSQL regression tests. Migration 009 preserves files and makes unproven legacy challenge visuals unavailable until re-uploaded.
- A persistence interleaving test caught a local edit arriving during awaited background-receipt cleanup. The active writer now checks its revision again before acknowledging completion, so that newer edit is saved by the same coalesced loop. Executable tests use the actual production loop and cover cleanup failure, background reconciliation, account changes and storage failure; the standard release performance gate includes them.
- The complete release checks cover static/native wiring, PostgreSQL authorization, calculated metrics and representative large local fixtures. They do not establish physical-device delivery, App Store acceptance or million-user capacity.
- No core paywalls were found or added. AI coaching, photo calorie estimation and paid country-specific food APIs remain explicitly deferred; see `FREE_CORE_AND_OPTIONAL_INTEGRATIONS.md`.
